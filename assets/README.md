# Assets

## `pipe/`

| File | What it is |
|---|---|
| `Real_sim.usd` | The pipe model that the simulator loads (USD crate, authored in Blender 5.1.1). |
| `Real_sim.stl` | The same mesh as a binary STL (3604 triangles, 1.23 x 2.13 x 0.50 m bounding box before scaling). Source geometry for other tools; not used at run time. |

The simulator spawns the USD with a uniform scale of 1.5 and a -90 degree rotation about Z, so that the pipe axis
runs along the world +X axis starting at the mouth where the rover is placed. After scaling the pipe is about
3.6 m long along its centre line with an inner diameter of 0.6 m (wall thickness 7.5 cm), and consists of a straight
section, a 45 degree bend, a diagonal section and a second 45 degree bend into a short straight end. The mesh has no
material; it renders as a plain grey wall unless `--pipe_texture` is used.

**The USD is not just the converted STL.** Besides the pipe mesh the Blender export contains the default objects of
the Blender scene: a `SphereLight` (intensity 318, radius 0.1), a `DomeLight` named `env_light` (intensity 1; its
texture `./textures/color_0C0C0C.exr` is not part of the repository, so it resolves to nothing) and a `Camera`.
They are instantiated together with the pipe and take part in the lighting of the simulated images. The file is kept
exactly as it was in the original project; a USD regenerated from the STL has the same geometry but not these lights.

## `textures/`

Not committed. On the first run the simulator writes the procedural images into this folder:
`ground_mud_1024_99.png`, `sky_overcast_2048x1024_88.png` and, with `--pipe_texture`, `pipe_corrosion_<size>_<seed>.png`
(the numbers are size and seed), using the generators in `pipe_rover/textures.py`. Generation takes about half a minute.
The images are pixel-identical to the ones generated by the original script (`tests/test_textures.py` checks this).

The Jetbot robot model is loaded from NVIDIA's Isaac asset server at run time (`ISAAC_NUCLEUS_DIR`) and is not part of
this repository.
